CONCLUSIONES - AUTOMATIZACION SWAGGER PETSTORE

1. El proyecto automatiza seis operaciones de usuario con Karate: crear, consultar, actualizar,
   consultar nuevamente, eliminar y verificar la inexistencia del usuario.

2. Las pruebas se apoyan en los endpoints de Swagger Petstore:
   POST /user
   GET /user/{username}
   PUT /user/{username}
   DELETE /user/{username}

3. Los escenarios son independientes entre sí. Cada uno genera un username único y crea sus propias
   precondiciones, lo cual permite ejecutarlos por etiqueta o como suite completa sin depender del orden.

4. La validación de actualización recupera el usuario actual, modifica solo firstName y email en el body
   PUT y luego realiza un GET para confirmar que los cambios fueron persistidos correctamente.

5. La validación de eliminación verifica la respuesta del DELETE y luego consulta el usuario para confirmar
   que ya no existe. El comportamiento observado para un registro inexistente es HTTP 404 con
   {"code":1,"type":"error","message":"User not found"}.

6. La especificación OpenAPI no define un status exitoso fijo para POST, PUT y DELETE. En las ejecuciones
   observadas contra la API pública, estas operaciones respondieron con HTTP 200 y un ApiResponse
   que contiene code, type y message.

7. El servicio externo es compartido y puede cambiar su comportamiento o disponibilidad. Debido a esto,
   la automatización no se basa únicamente en el código HTTP de la operación de escritura; además valida
   la persistencia con un GET posterior, evitando falsos positivos.

8. La solución está construida con Java 17, Maven, Karate 1.5.2 y JUnit 5. La ejecución genera
   reportes HTML estandar y el script de automatización guarda una copia en reports/karate-reports
   para conservar evidencia reproducible.

9. El resultado práctico del ejercicio es una suite funcional, modular y ejecutable por escenarios,
   con buena trazabilidad y posibilidad de análisis por etiqueta, request y response.
